# MER0042

## Summary

`MER0042` flags positional `true` and `false` arguments whose target parameter is a `bool`.

## Intent

The parameter name gives a boolean literal its meaning at the call site. This is especially useful when several boolean options appear together or when a framework API has a broad signature.

## What It Reports

The rule covers:

- method invocations
- constructor calls
- object creation expressions

Named arguments are already explicit and remain clear. The diagnostic points at the boolean literal and includes the target parameter name.

## What It Allows

- Named boolean arguments such as `completed: false`.
- Boolean expressions and variables whose meaning is carried by their local name.
- Arguments converted to non-boolean parameter types.

## Examples

### Method Call

Incorrect:

```csharp
ReadCompetitionFixtures(lease, clubId, false, cancellationToken);
```

Correct:

```csharp
ReadCompetitionFixtures(lease, clubId, completed: false, cancellationToken);
```

### Constructor Call

Incorrect:

```csharp
var writer = new StreamWriter(path, append: false, Encoding.UTF8, bufferSize, false);
```

Correct:

```csharp
var writer = new StreamWriter(
    path,
    append: false,
    Encoding.UTF8,
    bufferSize,
    leaveOpen: false);
```

## Current Analysis Scope

The analyzer resolves the method or constructor symbol and maps positional arguments to parameters. Test paths are outside the rule scope. The initial version reports literal boolean values supplied to parameters whose declared type is `bool`.

## Preferred Refactor

Add the parameter name at each positional boolean literal.
