# MER0036

## Summary

`MER0036` flags selector-only LINQ ordering calls whose key type is `string`, together with sorted string collections constructed without an explicit comparer.

## Intent

String ordering becomes part of a stable output contract when it feeds identifiers, hashes, persistence, generated files, or protocol data. An explicit comparer records the intended ordering semantics at the ordering site.

## What It Reports

Reports selector-only calls to the `System.Linq.Enumerable` ordering methods when the selector returns `string`:

- `OrderBy`
- `OrderByDescending`
- `ThenBy`
- `ThenByDescending`

It also reports construction of `SortedSet<string>` and `SortedDictionary<string, TValue>` when the constructor arguments contain no explicit `IComparer<string>` implementation.

## What It Allows

- An ordering overload that supplies `StringComparer.Ordinal`, `StringComparer.OrdinalIgnoreCase`, or another explicit string comparer.
- A sorted collection constructed with `StringComparer`, `Comparer<string>`, or a custom `IComparer<string>` implementation.
- Ordering whose key type is another type, such as an integer, enum, date, or strongly typed identifier.
- `Queryable` and other ordering APIs outside the initial `Enumerable` matcher.

## Examples

### Primary Ordering

Incorrect:

```csharp
var ordered = values
    .OrderBy(value => value.Code)
    .ToArray();
```

Correct:

```csharp
var ordered = values.OrderBy(value => value.Code, StringComparer.Ordinal);
```

### Secondary Ordering

Incorrect:

```csharp
var ordered = values
    .OrderBy(value => value.GroupId)
    .ThenBy(value => value.Code)
    .ToArray();
```

Correct:

```csharp
var ordered = values
    .OrderBy(value => value.GroupId)
    .ThenBy(value => value.Code, StringComparer.OrdinalIgnoreCase)
    .ToArray();
```

### Sorted Collections

Incorrect:

```csharp
var names = new SortedSet<string>();
var scores = new SortedDictionary<string, int>();
```

Correct:

```csharp
var names = new SortedSet<string>(StringComparer.Ordinal);
var scores = new SortedDictionary<string, int>(StringComparer.Ordinal);
```

### Choosing the Comparer

Use ordinal comparison for machine-stable keys, file names, protocol values, and identifiers:

```csharp
var files = fileNames.OrderBy(fileName => fileName, StringComparer.OrdinalIgnoreCase);
```

Use an explicit culture comparer when the order is presented as user-facing language:

```csharp
var labels = values.OrderBy(value => value.Label, StringComparer.CurrentCulture);
```

## Covered APIs

| API | Reported shape | Preferred repair |
| --- | --- | --- |
| `Enumerable.OrderBy` | String selector with one argument | Add an `IComparer<string>` argument |
| `Enumerable.OrderByDescending` | String selector with one argument | Add an `IComparer<string>` argument |
| `Enumerable.ThenBy` | String selector with one argument | Add an `IComparer<string>` argument |
| `Enumerable.ThenByDescending` | String selector with one argument | Add an `IComparer<string>` argument |
| `SortedSet<string>` | Construction without a string comparer | Supply the comparer constructor argument |
| `SortedDictionary<string, TValue>` | Construction without a string comparer | Supply the comparer constructor argument |

The matcher resolves the method and generic type symbols, so a variable or custom type that implements `IComparer<string>` forms the same explicit boundary as a static `StringComparer` property.

Culture-aware user-facing order can use an explicit culture comparer. Machine-stable data commonly uses `StringComparer.Ordinal` or `StringComparer.OrdinalIgnoreCase`.

## Preferred Refactor

Choose the comparer at the first ordering or sorted-collection boundary. Keep the choice close to the key selector so a later reader can distinguish machine-stable ordering from user-facing language order.
