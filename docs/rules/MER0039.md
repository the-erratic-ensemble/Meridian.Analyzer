# MER0039

## Summary

`MER0039` flags a `DbCommand` created from a connection with a locally active `DbTransaction` when execution occurs before that transaction is assigned.

## Intent

ADO.NET keeps command creation and transaction binding as separate operations. Assigning the active transaction before execution keeps the command inside the intended atomic scope.

## What It Reports

Reports an execution call when all of these facts are visible in the containing method:

- A local transaction comes from `DbConnection.BeginTransaction...` and returns a `DbTransaction`-derived value.
- A local command comes from `DbConnection.CreateCommand()` on the same connection, or from the transaction's `Connection` property.
- The command reaches `ExecuteReader`, `ExecuteReaderAsync`, `ExecuteScalar`, `ExecuteScalarAsync`, `ExecuteNonQuery`, or `ExecuteNonQueryAsync`.
- The command has no assignment of the same transaction to its `Transaction` property before execution.

The warning points at the execution call because that is where a command can leave the active transaction scope.

## What It Allows

- `command.Transaction = transaction` before the command executes.
- A command created from `transaction.Connection` and bound to that same transaction.
- Direct command expressions and simple local assignments that preserve the same connection and transaction symbols.
- Commands whose connection has no locally created transaction visible to this rule.
- Other execution APIs outside the supported `DbCommand` execution-method set.

## Examples

### Missing Binding

Incorrect:

```csharp
using var transaction = connection.BeginTransaction();
using var command = connection.CreateCommand();
command.CommandText = sql;
await command.ExecuteNonQueryAsync(cancellationToken);
```

Correct:

```csharp
using var transaction = connection.BeginTransaction();
using var command = connection.CreateCommand();
command.Transaction = transaction;
command.CommandText = sql;
await command.ExecuteNonQueryAsync(cancellationToken);
transaction.Commit();
```

### Reader Execution

The transaction binding applies to reads as well as writes:

```csharp
using var transaction = connection.BeginTransaction();
using var command = connection.CreateCommand();
command.Transaction = transaction;
command.CommandText = sql;

using var reader = await command.ExecuteReaderAsync(cancellationToken);
while (await reader.ReadAsync(cancellationToken))
    Consume(reader);
```

### Transaction-Owned Connection

Creating the command from the transaction connection keeps the relationship explicit:

```csharp
using var transaction = connection.BeginTransaction();
using var command = transaction.Connection!.CreateCommand();
command.Transaction = transaction;
command.CommandText = sql;
command.ExecuteNonQuery();
```

## Analysis Scope

The analyzer follows local synchronous transaction values, direct command creation, and exact local symbol identity. Awaited `BeginTransactionAsync` result tracking, transaction lifetime across branches, and configured transaction-aware factories require an expanded operation-block contract.

## Preferred Refactor

Create the command from the connection participating in the transaction, assign `DbCommand.Transaction` immediately, and execute only after the assignment. Keep the transaction and command in the same using scope so their lifetimes remain visible together.
