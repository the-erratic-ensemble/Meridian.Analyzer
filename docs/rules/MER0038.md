# MER0038

## Summary

`MER0038` flags successful `SemaphoreSlim.Wait` and awaited `WaitAsync` calls when one release in a covering `finally` block or transfer to a disposable lease/releaser owner is absent.

## Intent

Each successful wait consumes semaphore capacity. The release owner keeps that capacity available when work completes or throws.

## What It Reports

Reports successful semaphore acquisitions represented by:

- `SemaphoreSlim.Wait(...)` overloads that return `void`.
- Awaited `SemaphoreSlim.WaitAsync(...)` overloads that return non-generic `Task`.

The diagnostic points at the acquisition when the same semaphore receiver has no visible release owner. A direct release qualifies when exactly one matching `Release` call appears in a `finally` block that covers the acquisition and the work after it.

## What It Allows

- A matching `Release()` in a covering `finally` block.
- An acquisition transferred directly to a returned disposable type whose name ends in `Lease` or `Releaser`.
- An acquisition transferred into a local `Lease` or `Releaser` value that is later returned from the method.
- `SemaphoreSlim.Wait(...)` overloads that return `bool` and `WaitAsync(...)` overloads that return `Task<bool>`, where success is represented by the returned value and belongs to a separate success-state shape.
- Test paths, which are outside the production ownership rule.

## Examples

### Direct Release

Incorrect:

```csharp
await gate.WaitAsync(cancellationToken);
await WorkAsync(cancellationToken);
```

Correct:

```csharp
await gate.WaitAsync(cancellationToken);
try {
    await WorkAsync(cancellationToken);
}
finally {
    gate.Release();
}
```

### Timeout-Aware Acquisition

The `Task<bool>` overload makes successful acquisition explicit to the caller:

```csharp
if (!await gate.WaitAsync(
        TimeSpan.FromSeconds(1),
        cancellationToken))
    return false;

try {
    await WorkAsync(cancellationToken);
    return true;
}
finally {
    gate.Release();
}
```

### Disposable Owner

An owner can carry release responsibility across a method boundary:

```csharp
public async Task<IAsyncDisposable> AcquireAsync(
    CancellationToken cancellationToken) {
    await gate.WaitAsync(cancellationToken);
    return new GateLease(gate);
}
```

`GateLease` should release the same semaphore from its `DisposeAsync` implementation. The analyzer recognizes the `Lease` or `Releaser` name together with `IDisposable` or `IAsyncDisposable`.

### Acquisition Flag

An acquisition flag keeps release conditional when the wait can throw before capacity is acquired:

```csharp
var acquired = false;
try {
    await gate.WaitAsync(cancellationToken);
    acquired = true;
    await WorkAsync(cancellationToken);
}
finally {
    if (acquired)
        gate.Release();
}
```

## Analysis Scope

The analyzer uses semaphore receiver identity, visible release calls, and the covering `finally` shape. Sequential acquisitions on one receiver, branch joins, and more complex owner contracts require path-state analysis that follows each successful acquisition separately.

## Preferred Refactor

Place the work protected by the semaphore inside a `try` block and release the same receiver from `finally`. Use a named disposable lease when the acquisition must move to another method or object.
