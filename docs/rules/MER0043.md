# MER0043

## Summary

`MER0043` flags position-based LINQ selection from dictionary and set data before an explicit ordering step.

## Intent

Dictionary and set enumeration can expose an order without making that order part of the source contract. Ordering the data before selecting a position makes the selected item reproducible and reviewable.

## What It Reports

The rule covers `System.Linq.Enumerable` chains ending in:

- `First` and `FirstOrDefault`
- `Last` and `LastOrDefault`
- `ElementAt` and `ElementAtOrDefault`
- `Take` and `Skip`

It follows direct dictionary and set sources, `Keys`, `Values`, and common LINQ transformations. `OrderBy`, `OrderByDescending`, `ThenBy`, or `ThenByDescending` establishes the selection order.

## What It Allows

- A predicate selection that does not depend on a position.
- A positional operation after an explicit ordering chain.
- Lists, arrays, and other ordered source types outside the dictionary and set boundary.
- Membership and size operations such as `Any`, `All`, `Contains`, and `Count`.

## Examples

### Dictionary Keys

Incorrect:

```csharp
var role = rolePositionBands.Keys.First(candidate => IsEligible(candidate));
```

Correct:

```csharp
var role = rolePositionBands.Keys
    .OrderBy(candidate => candidate, StringComparer.Ordinal)
    .First(candidate => IsEligible(candidate));
```

### Dictionary Values

Incorrect:

```csharp
var match = playerMatches.Values.FirstOrDefault(IsOffendingMatch);
```

Correct:

```csharp
var match = playerMatches.Values
    .OrderBy(candidate => candidate.MatchId)
    .FirstOrDefault(IsOffendingMatch);
```

## Current Analysis Scope

The initial proof follows LINQ source expressions through order-preserving fluent calls and recognizes dictionary, set, and their generic interfaces by symbol. It reports the position-based operation whose input still has unordered state.

## Preferred Refactor

Choose the key that defines the required order and apply an explicit ordering operation before selecting a position.
