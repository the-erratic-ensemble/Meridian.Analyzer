# MER0048

## Summary

`MER0048` flags `Exception.Message` and `Exception.ToString()` when their text contributes directly to a branch condition or catch filter.

## Intent

Exception text is presentation data. Exception types, error codes, and structured properties provide stable identities for control flow.

## What It Reports

The rule covers exception text used in:

- `if`, `while`, `do`, and `for` conditions
- conditional expressions
- switch statements and switch expressions
- catch filters
- comparisons and string or regular-expression operations nested in those conditions

The receiver can be `System.Exception` or a derived exception type.

## What It Allows

- Logging, diagnostics, and user-facing reporting of exception text.
- Exception type patterns such as `exception is TimeoutException`.
- Structured error properties and application error codes in branch conditions.

## Examples

### Message Comparison

Incorrect:

```csharp
if (exception.Message.Contains("timeout", StringComparison.Ordinal))
    retry = true;
```

Correct:

```csharp
if (exception is TimeoutException)
    retry = true;
```

### Catch Filter

Incorrect:

```csharp
catch (Exception exception) when (exception.ToString().Contains("retry")) {
    Retry();
}
```

Correct:

```csharp
catch (RetryableOperationException) {
    Retry();
}
```

## Current Analysis Scope

The first proof follows direct `Message` member access and exception receiver `ToString()` calls into the containing branch expression. A message assigned to an intermediate local before a later branch belongs to a wider data-flow analysis.

## Preferred Refactor

Branch on exception types or structured error identity and reserve exception text for reporting.
