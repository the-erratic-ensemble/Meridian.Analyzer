# MER0035

## Summary

`MER0035` requires cancellation propagation from matching async route boundaries that use `CancellationToken.None`.

## Intent

Sidecar and JSON-RPC route handlers are request boundaries. Passing `CancellationToken.None` prevents request or host shutdown cancellation from reaching downstream database and application work.

The rule reports once at a route method when the boundary has no token. After a token is added, it reports any remaining `CancellationToken.None` use inside that route.

## What It Reports

The rule targets async `Handle*Async` methods on `*Routes` classes that accept a request-shaped parameter.

It reports:

- a route using `CancellationToken.None` with no accepted `CancellationToken`
- `CancellationToken.None` inside a route that already accepts a `CancellationToken`

The analyzer scope is limited to matching route methods in non-test paths. Every `CancellationToken.None` member access inside a matching route is in scope, including cleanup, rollback, disposal, and cancellation-finalisation code in that method.

`CA2016` remains responsible for forwarding an available token deeper in the call chain.

## Examples

Incorrect:

```csharp
public Task<ClubResult> HandleGetClubAsync(JsonRpcRequest request) {
    return _handler.HandleAsync(request.Payload, CancellationToken.None);
}
```

Correct:

```csharp
public Task<ClubResult> HandleGetClubAsync(
    JsonRpcRequest request,
    CancellationToken cancellationToken) {
    return _handler.HandleAsync(request.Payload, cancellationToken);
}
```

## Preferred Refactor

Expose the request or host lifetime token at the route boundary and forward it. Keep intentional cleanup-specific `CancellationToken.None` usage outside the matching route boundary.
