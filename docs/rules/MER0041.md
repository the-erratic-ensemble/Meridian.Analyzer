# MER0041

## Summary

`MER0041` flags a null-forgiving operator applied to a literal `null` or a default value.

## Intent

Literal null and default values describe an intentional state. A nullable type, result shape, or state-bearing record keeps that state visible to callers.

## What It Reports

The rule reports:

- `null!`
- `default!`
- `default(T)!`

Parenthesized forms of these operands are included. The diagnostic includes the default operand type when the type is available.

## What It Allows

- Null suppression on a normal expression such as `value!`, which belongs to nullable-flow analysis.
- A default value without a null-forgiving operator.
- Explicit nullable output or state-bearing result types.

## Examples

### Literal Null

Incorrect:

```csharp
return null!;
```

Correct:

```csharp
return null;
```

### Default State

Incorrect:

```csharp
var empty = default(FixtureSlot<Club>)!;
```

Correct:

```csharp
var empty = default(FixtureSlot<Club>);
```

## Current Analysis Scope

The first proof is syntax-based and covers literal null, the default literal, and typed default expressions. It excludes test paths and leaves ordinary expression suppression to the compiler’s nullable analysis.

## Preferred Refactor

Represent the empty or missing state in the type contract, a result type, or an explicit state field.
